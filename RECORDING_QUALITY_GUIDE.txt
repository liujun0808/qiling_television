Qiling Television 录制数据自检说明
更新日期：2026-09-04

一、当前录制数据的目标规范

本项目当前面向右手操作任务，单条成功 episode 应满足：

1. 三路 RGB（head、left、right）均为原始相机输出的 JPEG：640 x 480 @ 30Hz。
   不进行录制端 resize、裁剪或旋转。
2. observation、右臂关节 action、右手二值 gripper action 以同一采样时刻写入，目标频率 50Hz。
3. observation 只含右臂 7 个关节的位置 q 和速度 dq；不录制关节力矩等低层状态。
4. arm action 为右臂 7 个关节的目标位置；gripper action 为右手 O6 开合目标（0=张开，1=闭合）。
5. 每个成功 episode 含唯一且非空的语言任务标签；失败 episode 不保存到 recordings/episode_*。

二、自检程序与严格判定规则

离线自检命令：

  ros2 run qiling_recording_real check_episode_quality \
    recordings/episode_YYYYMMDD_HHMMSS_mmm

该命令只读取 MCAP 和 episode 元数据；不会启动 ROS 节点、发布控制命令或调用控制服务。

当前自检分为“可转换的结构完整性”与“仅告警的时序质量”两类：

1. episode/status 为 success，且 saved=true；语言标签有效；必需 topic 齐全。
2. 三路图像均为 JPEG，且每一帧均为 640 x 480。
3. JPEG 格式/尺寸、右臂字段维度和 gripper 取值必须正确；缺 topic、空数据或损坏数据会导致 `OVERALL: FAIL`，无法转换。
4. 图像平均频率 >= 28.50Hz、图像最大间隔 <= 0.1000 秒、50Hz state/action 连续性、原子批次和队列丢弃均只输出 `WARN`，不会阻断转换。

注意：图像的 0.10 秒门限用于识别连续性风险。30Hz 的正常相邻间隔约为 0.033 秒；超过 0.10 秒表示该相机在这段时间至少连续缺失了多帧或消息未被录制，但当前流程仍会转换该 episode。

四、非严格通过数据能否转换和训练

可以转换，但“能够转换”与“适合作为训练样本”是两个不同的判断。

1. 转换可行性
   这批非严格通过的数据没有发现 MCAP 写入错误、JPEG 损坏、图像尺寸错误或字段格式错误。因此转换程序可以读取并转出其有效帧，不会因为格式本身失败。

2. 训练风险
   风险来自时间不同步，而不是数据格式。图像在掉帧区间缺少真实视觉观测，但 action 仍持续变化；若转换时把距离很远的旧图像硬对齐到当前 action，VLA 会看到“过时画面 + 当前动作”的错误配对。
   对缓慢、无遮挡的移动，偶发约 0.10～0.14 秒间隔的影响可能有限；但抓取、接触、放入容器等快速关键阶段，哪怕一小段错配也会降低训练数据质量。

3. 建议的数据使用分级
   A. 直接使用：上述 14 条严格通过数据。
   B. 有条件使用：其余 59 条。先查看各条自检中每一路的 rate 和 max_gap，再决定是否保留。转换时应按每路相机真实时间戳选择最近图像，并设定最大允许对齐误差；对掉帧附近的时间段丢弃训练样本，而不是复制上一帧图像来伪造连续观测。它们可作为补充数据，但不宜先于严格通过数据进入第一版训练集。
   C. 重采：上述 17 条明显掉帧数据，特别是 164113_922。对于三视角模型，任何一路相机的严重缺失都会影响样本；若未来模型完全不使用左相机，才可重新仅按实际使用的模态评估左相机问题。

五、当前掉帧定位结论

录制器已将状态/action 与 JPEG 编码/MCAP 写入拆成独立线程和队列。已检查的一条历史 episode 中，图像接收数、编码数、入 writer 队列数和写入数一致，且没有编码、队列或写入错误；同时 bag 中记录的相机 header 时间戳自身存在大间隔。

因此，当前主要矛盾不在 MCAP writer 或 JPEG 落盘，而在“相机设备 -> RealSense 驱动 -> ROS 图像发布/订阅回调”这条上游链路。仍需实验区分是 USB/相机源端丢帧，还是 ROS 进程调度造成订阅接收不连续。

六、后续录制前的修复与验证方案（建议按顺序执行）

步骤 1：建立无录制负载的基线。
  只启动三路相机，在不启动 recorder 的条件下，分别持续观察三路 image_raw 的频率和 header 时间戳间隔至少 60 秒。若此时已经掉帧，问题在相机/USB/驱动侧；若此时稳定、开启 recorder 后才掉帧，再检查主机 CPU、ROS 调度与订阅 QoS。

步骤 2：改善 USB 拓扑和供电。
  当前三台相机位于同一个 xHCI 根控制器下，两台 D405 还经过同一个 5Gbps hub。优先让 D435i、左 D405、右 D405 使用不同的 USB 根控制器/独立 PCIe USB 控制器；使用短而质量可靠的 USB3 数据线；必要时使用供电充足的 USB3 hub。不要把其它高带宽设备接到相同 hub。

步骤 3：排除相机进程和主机资源竞争。
  录制前关闭 RealSense Viewer、浏览器、可视化程序和不必要的图像订阅者。录制测试时观察 CPU 利用率、上下文切换、USB 内核日志和各相机节点进程的调度延迟。当前录制端队列没有丢弃，不代表相机驱动线程一定没有被主机调度延迟影响。

步骤 4：保持原生相机 profile，不通过 resize 补救。
  继续由 RealSense 驱动直接输出 640 x 480 @ 30Hz；不要用 1280 x 720 再缩放到 640 x 480。这样能减少 USB、拷贝和编码负载。若相机驱动支持直接发布压缩图像，可在完成基线对比后评估是否采用；前提是仍能确保 JPEG 内容、尺寸和时间戳正确。

步骤 5：在确认基线后再调整 recorder 调度/QoS。
  若三路裸相机稳定而一开启 recorder 就不稳定，再针对相机订阅使用 keep-last=1 的传感器数据 QoS、CPU 核绑定/优先级、编码线程数和队列深度做逐项 A/B 测试。一次只改一个变量，并用本自检程序比较结果，避免无法定位改善来源。

步骤 6：录制后的准入流程。
  每批数据录制完成后先逐条运行自检：严格通过的直接入库；轻微图像告警的先单独存放并在转换时按时间戳剔除异常窗口；明显掉帧或 state/action 不连续的 episode 重采。不要仅因“MCAP 能打开”就混入训练集。

七、转换阶段的时间对齐原则

相机是 30Hz，右臂 state/action 是 50Hz，二者天然不是同频。当前转换以每个头部图像时间戳作为时间轴；某一路掉帧时使用该路最近的可用图像或状态，保留完整 episode，不再删帧或切段。该策略满足“所有成功 episode 都转换”的需求，但会在掉帧处引入视觉/动作时间错配。
